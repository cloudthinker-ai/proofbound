# Proofbound 0.1.1

Security patch for the experimental Rust-backed Python proof-contract library.

`@requires` now rejects callable instances, including partials of those instances.
They could previously be classified as synchronous even when their `__call__`
method returned a coroutine or generator, allowing deferred bodies to start
after proof scope expiry. Ordinary Python functions, bound methods and their
partials remain supported. Protect a bound async `__call__` method explicitly
when needed; verification happens when awaited, before its body begins.
Generator and async-generator functions remain unsupported.
Partial subclasses are rejected, and built-in partials capture their bindings
at decoration so later keyword rebinding cannot separate checked subjects from
the arguments used by the operation.

`gdp-lint` now reports unreadable source directories as GDP000 and fails the
command. In 0.1.0, an unreadable root or child directory could be skipped and
the incomplete scan reported as successful. Readable sources retain the same
diagnostics and explicit roots remain respected.

Upgrade from [gdp-rs 0.1.1 on PyPI](https://pypi.org/project/gdp-rs/0.1.1/).
The distribution remains `gdp-rs`, import `gdp`, CLI `gdp-lint`. Wheels cover
Linux x64/ARM64, macOS ARM64 and Windows x64 with CPython 3.11–3.14. Rust core
semantics and Python extension interface version 1 are unchanged.

Repository hardening includes secret scanning, push protection, automated
Dependabot security updates and weekly Cargo, Python and Actions updates.
Main requires the nine CI jobs and reviewed pull requests; workflows run for
every PR so documentation changes also produce required checks.

Proofbound builds on Guillermo Rauch's [gdp-ts](https://github.com/rauchg/gdp-ts)
and research by Matt Noonan and Ollie Charles. Original MIT license bytes and
attribution are preserved. Policy correctness, permission revocation, mutable
values and atomic check/write remain application responsibilities.
